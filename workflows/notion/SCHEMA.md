# Notion数据库结构设计

## 🎯 设计原则

1. **通用化**：字段设计适配任何产品/行业
2. **标准化**：统一的字段命名和类型
3. **可扩展**：易于添加自定义字段
4. **关联性**：数据库之间清晰的关联关系
5. **自动化友好**：字段类型适合API操作

---

## 📊 数据库总览

```
热点库 (Hotspot DB)
    ↓ 筛选
素材库 (Material DB)
    ↓ 匹配
产品库 (Product DB)
    ↓ 生成
内容库 (Content DB)
    ↓ 发布
发布库 (Publish DB)
    ↓ 监测
数据库 (Analytics DB)
    ↓ 优化
策略库 (Strategy DB)
```

| 关键词 | Multi-select | 提取的关键词 | MBTI, 人格, 测试 | ✅ |
| 分类 | Multi-select | 内容分类 | 心理/社交/娱乐 | ✅ |
| 目标受众 | Multi-select | 受众标签 | 年轻人/白领/学生 | - |
| 情感倾向 | Select | 情感分析 | 正面/中性/负面 | - |
| 状态 | Select | 处理状态 | 待筛选/已筛选/已使用/已废弃 | ✅ |

### 索引字段
- `来源` + `发现时间`：按来源查看时间线
- `热度值` + `状态`：筛选高热度待处理

### 视图设计
1. **待筛选**：状态=待筛选，按热度值降序
2. **高热度**：热度值≥80，按发现时间降序

4. **本周热点**：发现时间=本周，按热度值降序

## 🔗 数据库关联关系

```
热点库 ──1:N──> 素材库
素材库 ──N:M──> 产品库 (通过标签匹配)
素材库 + 产品库 ──> 内容库
内容库 ──1:1──> 发布库
发布库 ──1:N──> 数据库 (时间序列)
数据库 ──> 策略库 (分析优化)
```

## 🚀 API友好设计

所有字段类型选择考虑API操作便利性：
- ✅ Title: 唯一标识，易于查询
- ✅ Select: 标准化值，易于筛选
- ✅ Multi-select: 标签系统，易于匹配
- ✅ Number: 数值计算，易于排序
- ✅ Date: 时间序列，易于筛选
- ✅ Relation: 数据关联，易于追溯
- ✅ Rich Text: 长文本，支持Markdown
