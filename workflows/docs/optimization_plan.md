
### 新增工作流

#### 1. mbti-content-creator.json
**功能**：基于素材库和产品库，自动生成小红书和公众号内容

**节点设计**（分步式，14个节点）：
```
1. 定时触发/手动触发
2. 查询Notion素材库（热度≥8，状态=可用）
3. 查询Notion产品库（获取4款产品）
4. 选择素材（随机1条）
5. 选择产品（随机1-2款）
6. AI生成小红书标题
7. AI生成小红书正文
8. AI生成小红书标签
9. AI生成公众号标题
10. AI生成公众号正文
11. 整合小红书内容
12. 整合公众号内容
13. 写入创作库（小红书）
14. 写入创作库（公众号）
15. 生成执行摘要
```

**执行频率**：周一、三、五 早上9点

**输出**：
- 创作库中新增2条内容（状态：待审核）
- 执行摘要报告

---

#### 2. mbti-content-publisher.json
**功能**：将审核通过的内容发布到小红书和公众号

**节点设计**（分步式，10个节点）：
```
1. 手动触发（需要人工确认）
2. 查询创作库（状态=已审核，平台=小红书）
3. 查询创作库（状态=已审核，平台=公众号）
4. 准备小红书发布数据
5. 调用小红书API/Webhook发布
6. 更新小红书发布状态
7. 准备公众号发布数据
8. 调用公众号API发布
9. 更新公众号发布状态
10. 生成发布报告
```

**执行方式**：手动触发（审核后）

**输出**：
- 内容发布到平台
- 创作库状态更新为"已发布"
- 记录发布时间

---

#### 3. mbti-data-monitor.json
**功能**：定期抓取已发布内容的数据表现

**节点设计**（分步式，12个节点）：
```
1. 定时触发（每天晚上10点）
2. 查询创作库（状态=已发布，最近7天）
3. 提取小红书内容ID
4. 提取公众号内容ID
5. 调用小红书API获取数据
6. 解析小红书数据（阅读/点赞/评论）
7. 调用公众号API获取数据
8. 解析公众号数据（阅读/点赞/评论）
9. 更新创作库数据（小红书）
10. 更新创作库数据（公众号）
11. 生成数据分析报告
12. 识别高表现内容
```

**执行频率**：每天晚上10点

**输出**：
- 创作库数据更新
- 数据分析报告
- 高表现内容列表

---

#### 4. mbti-material-enhancer.json
**功能**：优化现有素材库，补充创作角度和详细内容

**节点设计**（分步式，10个节点）：
```
1. 定时触发/手动触发
2. 查询素材库（状态=待评估）
3. 读取素材原文链接
4. 抓取完整网页内容
5. AI深度分析（提取金句、用户评论）
6. AI生成创作角度（5个方向）
7. AI生成详细内容（扩展摘要）
8. 计算热度评分
9. 更新素材库
10. 生成优化报告
```

**执行频率**：每天下午3点

**输出**：
- 素材库状态更新为"可用"
- 补充创作角度和详细内容

## 🔧 技术规范

### 1. 环境变量标准化

```bash
# Notion
NOTION_API_TOKEN=secret_xxx
NOTION_MATERIAL_DATABASE_ID=2d87fa67a9af81b99b07cde5013942b4
NOTION_PRODUCT_DATABASE_ID=xxx
NOTION_CREATION_DATABASE_ID=xxx

# AI服务
AI_API_BASE_URL=http://localhost:8045
AI_MODEL=claude-sonnet-4-5-thinking
OPENAI_API_KEY=sk-xxx  # 备用

# 搜索服务
SERPAPI_KEY=xxx

# 社交媒体（未来）
XIAOHONGSHU_API_KEY=xxx
XIAOHONGSHU_API_SECRET=xxx
WECHAT_APPID=xxx
WECHAT_APPSECRET=xxx
```

### 2. 节点命名规范

**格式**：`动词-名词` 或 `名词-动词`

**示例**：
- ✅ `query-material-database` (查询素材库)
- ✅ `generate-xiaohongshu-title` (生成小红书标题)
- ✅ `write-creation-database` (写入创作库)
- ❌ `node1`, `process`, `handle`（不清晰）

### 3. 节点ID规范

**格式**：kebab-case

**示例**：
- ✅ `schedule-trigger`
- ✅ `ai-analysis`
- ✅ `write-notion`
- ❌ `ScheduleTrigger`, `ai_analysis`

### 4. 容错策略

**必须启用continueOnFail的节点**：
- 网页抓取（可能失败）
- AI API调用（可能超时）
- Notion写入（可能重复）
- 社交媒体API（可能限流）

**示例**：
```json
{
  "id": "fetch-webpage",
  "continueOnFail": true,
  "retryOnFail": true,
  "maxTries": 3
}
```

### 5. 超时设置

**建议值**：
- 网页抓取：30秒
- AI分析：60秒
- Notion操作：10秒
- 社交媒体API：30秒
